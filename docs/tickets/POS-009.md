# POS-009 — Struk dan riwayat transaksi

Status: Selesai
Prioritas: P1
Dependensi: POS-008

## Tujuan

Struk menggunakan snapshot transaksi API, cetak browser, pencarian dan filter riwayat.

## Kriteria penerimaan

- [x] Struk menampilkan nomor/waktu Jakarta, toko, pelanggan, item, diskon, metode, dan kembalian.
- [x] Struk lama tetap sama setelah nama/harga produk atau pengaturan toko diubah.
- [x] Riwayat mendukung tanggal, pencarian dan pagination; detail tidak bocor antar workspace.
- [x] Cetak hanya area struk; dialog accessible dan dapat ditutup dengan Escape.

## Verifikasi tanpa unit test

1. Coba buka/cetak struk baru dan lama; lihat print preview.
2. Edit produk lalu buka struk lama; filter dan halaman riwayat diperiksa.

## Implementasi

- **Halaman `/transaksi`** (`pages/TransactionsPage.jsx`, `components/transactions/`) untuk kasir dan pemilik:
  - Pencarian nomor/pelanggan dengan debounce 300 ms, dan filter tanggal `type="date"` (hari Asia/Jakarta, `max` hari ini) dengan tombol "Hari ini" dan "Semua tanggal".
  - Perubahan filter kembali ke halaman pertama.
  - Tabel berisi nomor dan waktu WIB, pelanggan, jenis pesanan, jumlah item, metode, total, dan tombol "Lihat struk"; di ≤720 px tabel menjadi kartu (`.card-table`, dipakai bersama tabel Produk).
- **Paginasi** 20 per halaman. Rentang "21–31 dari 31" dihitung dari `offset` respons server, jadi label selalu cocok dengan baris yang tampil. Tombol nonaktif saat memuat, dan tabel diredupkan selama `aria-busy`.
- **Data** (`hooks/useTransactions.js`, `useTransactionDetail.js`, `lib/transactions-api.js`): `GET /api/transactions` dan `/:id` dengan abort per perubahan dan validasi bentuk respons. Data lama tetap tampil saat gagal ("Riwayat belum diperbarui" + Coba lagi).
- **Struk lama** (`TransactionReceiptDialog`): selalu dimuat ulang dari detail server (snapshot), dengan status memuat, error dan coba lagi, serta tombol cetak yang nonaktif sampai struk siap.
- **Dialog struk bersama** (`components/receipt/ReceiptModal.jsx`):
  - `<dialog>` modal yang dirender lewat portal langsung di `<body>`; Escape menutup dan fokus kembali ke pemicu.
  - Header, catatan, dan tombol diberi kelas `.no-print`.
  - Dipakai struk sukses di Kasir (kini punya tombol **Cetak struk**) dan struk riwayat.
- **Cetak** (`@media print`): bila `body` memiliki `.receipt-portal`, semua anak `body` lain disembunyikan dan dialog menjadi statis selebar ≤80 mm tanpa bayangan. Logo memakai `print-color-adjust: exact`. Tanpa dialog struk, Ctrl+P mencetak halaman seperti biasa.

  - Daftar diblokir saat mencari → "Riwayat belum diperbarui" dengan baris lama tetap; Coba lagi → 7 transaksi.

## Review dan verifikasi ulang

Review pada 15 Oktober 2026 dengan Chrome headless/Playwright, build produksi Express, port acak, database dan konteks browser sementara. Teks PDF diekstrak dengan PDFKit macOS untuk memeriksa isi tiap halaman. Tidak menambah unit test, dependency, atau artefak cetak ke repo.

- **Pencarian dan pagination:** pencarian `raka` bersamaan dengan klik Berikutnya sebelumnya menghasilkan tabel kosong, meski server memiliki enam hasil. Pagination kini terkunci selama debounce, dan halaman direset ketika kata kunci efektif berubah. Halaman di luar rentang otomatis kembali ke halaman valid; rentang kosong tidak ditampilkan sebagai angka terbalik.
- **Metadata respons:** limit 0/di atas 100, offset negatif/di atas 100.000, jumlah baris melebihi limit, atau rentang yang melampaui total kini ditolak dengan error yang bisa dicoba ulang. Tujuh respons daftar rusak diperiksa, termasuk tipe pelanggan invalid; tidak ada `pageerror`.
- **Teks panjang:** nama pelanggan 60 karakter tanpa spasi sebelumnya membuat tabel ponsel dan struk melebar. Kolom pelanggan, nominal kartu, dan teks struk kini dapat membungkus; label serta harga tetap terbaca. Halaman/tabel/dialog diperiksa pada 360/768/1280px tanpa overflow. Nama menu 60 karakter juga tercetak lengkap.
- **Cetak sebelum detail siap:** Ctrl+P saat struk memuat sebelumnya menyembunyikan seluruh halaman tanpa struk, sehingga hasilnya kosong. Aturan cetak kini mengisolasi portal hanya bila isi struk tersedia. Saat memuat atau error, portal disembunyikan dan halaman riwayat tetap dapat dicetak; tombol Cetak tetap nonaktif sampai detail siap.
- **PDF pendek/panjang:** struk contoh PRD dicetak satu halaman dengan toko, nomor, waktu WIB, pelanggan, item, subtotal 80.000, diskon 8.000, total 72.000, tunai/kembalian, dan label demo. Struk 50 item tercetak dalam beberapa halaman; seluruh nama item, teks panjang, total, serta footer ada, tanpa navigasi/header dialog/tombol. Baris item dan blok total dijaga agar tidak terbelah saat pergantian halaman.
- **Data dan filter nyata:** daftar 20 per halaman, tanggal WIB, Hari ini/Semua tanggal, pencarian nama/nomor/`%`, serta baris dan rentang selama respons tertunda sesuai API. Pencarian kembali ke halaman pertama, dan berkurangnya data ketika retry tidak meninggalkan halaman kosong.
- **Snapshot/isolasi:** struk serta PDF lama tetap menampilkan Seduh Coffee dan Kopi Susu Seduh Rp28.000 setelah menu/toko diubah. Detail workspace asing 404 dan daftar tidak memuat ID transaksi asal.
- **Error/fokus:** detail dan daftar gagal bisa dicoba ulang; daftar lama tetap tampil. Escape mengembalikan fokus ke tombol Lihat struk. Screenshot desktop serta dialog dengan nama panjang 360px diperiksa visual.
- Regresi POS-006 (sesi/peran/redirect), POS-007 (CRUD, validasi, snapshot, responsif), dan POS-008 (retry 408/respons hilang, stok/harga, struk setelah navigasi, pembayaran dan 401) lolos pada database baru.
- `npm run check`, aturan fungsi maksimal 25 baris, `integrity_check`/`foreign_key_check`, serta `git diff --check` lolos. Tidak ada error JavaScript browser atau error 500 nyata dari server pada verifikasi akhir.

Batas tahap ini:

- Filter dan halaman riwayat tidak disimpan di URL; refresh kembali ke halaman 1 tanpa filter.
- Print preview diverifikasi lewat emulasi media print dan PDF Chrome headless. Dialog cetak sistem dan printer fisik/thermal tidak diuji.
- Pencarian tidak peka huruf besar/kecil hanya untuk huruf ASCII (perilaku SQLite `LIKE`).
- Format tampilan input tanggal mengikuti locale browser.
- Firefox dan Safari belum diuji. Selektor `:has()` untuk cetak membutuhkan Firefox 121+ atau Safari 15.4+.
