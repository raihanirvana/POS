# POS-008 — Kasir React dan pembayaran

Status: Belum dimulai
Prioritas: P0
Dependensi: POS-005, POS-006

## Tujuan

Port menu, pencarian/kategori, pesanan, diskon, checkout tunai/QRIS simulasi ke API transaksi.

## Kriteria penerimaan

- [ ] Menu diambil dari API; keranjang dipisahkan dari data domain server.
- [ ] Panel pesanan desktop/mobile mendukung jumlah, hapus, pelanggan, dan jenis pesanan.
- [ ] Tombol konfirmasi menahan submit ganda; idempotency key dipertahankan saat retry jaringan.
- [ ] Preview total di frontend dan hasil final server konsisten; perubahan harga/stok ditangani.
- [ ] Checkout sukses memperbarui stok dan membuka struk; gagal mempertahankan keranjang.
- [ ] QRIS tetap jelas simulasi; tidak ada gateway atau QR pembayaran fiktif.

## Verifikasi tanpa unit test

1. Coba alur kasir utuh di desktop dan ponsel.
2. Coba uang kurang, stok berubah, klik ganda, dan retry setelah respons jaringan hilang.

Belum tersedia. Isi perintah, hasil, dan keterbatasan yang benar-benar diperiksa saat tiket diselesaikan.
