# POS-007 — Halaman produk React

Status: Selesai
Prioritas: P1
Dependensi: POS-004, POS-006

## Tujuan

Hubungkan tabel produk, form tambah/edit, konfirmasi hapus, dan stok ke API.

## Kriteria penerimaan

- [x] Pemilik dapat mengelola menu; kasir tidak diberi kontrol pengelolaan.
- [x] Form punya label, validasi, loading, error server, dan konfirmasi hapus.
- [x] Data berasal dari API dan bertahan saat halaman dimuat ulang.
- [x] Nama/deskripsi ditampilkan aman sebagai teks; foto preset lokal digunakan.

## Verifikasi tanpa unit test

1. Tambah/edit/hapus via browser; refresh dan cek hasil di API.
2. Coba stok nol, masukan markup, dan API gagal; form menampilkan pesan yang membantu.

## Implementasi

- **`pages/ProductsPage.jsx`** + `hooks/useProductsPage.js`: header dengan tombol Tambah, toolbar pencarian (debounce 300 ms) dan filter kategori yang diteruskan ke query API, daftar, pesan sukses (`role="status"`, hilang setelah 5 detik), dan catatan stok.
- **`hooks/useProducts.js`**: GET `/api/products` dengan `AbortController` per perubahan filter. Data lama tetap tampil saat memuat ulang atau gagal ("Daftar belum diperbarui" + Coba lagi). Setelah simpan/hapus, daftar dimuat ulang dari server.
- **Tabel** (`components/products/`): foto preset, nama, label, deskripsi, kategori, harga rupiah, dan pill stok (Habis/≤10/normal). Aksi Edit dan Hapus memakai `aria-label` per produk. Di ≤720 px baris menjadi kartu; di 721–950 px tombol Edit hanya ikon.
- **Form** (`ProductFormDialog`, `useProductForm`, `lib/product-form.js`):
  - `<dialog>` modal dengan label dan petunjuk. Validasi klien sama dengan server, dan fokus pindah ke field pertama yang salah.
  - Error 400 server dipetakan ke `fields`; error lain tampil di atas tombol simpan dengan kode permintaan.
  - Tombol menampilkan "Menyimpan…"; Escape diblokir saat menyimpan; fokus kembali ke tombol pemicu.
  - Harga/stok memakai `inputMode="numeric"` dan menampilkan pratinjau rupiah.
  - Edit hanya mengirim field yang berubah (PATCH), sehingga stok hasil checkout tidak tertimpa.
- **Foto:** pemilih preset hanya menampilkan foto kategori terpilih. Ganti kategori mempertahankan foto bila cocok, selain itu kembali ke default (Kopi `latte`, Non-kopi `matcha`, Pastry `croissant`) seperti server. Foto disalin dari prototype ke `client/src/assets/menu/` beserta `SOURCES.md`, lalu di-bundle Vite.
- **Hapus:** `ConfirmDialog` dengan teks bahwa struk lama tetap aman. Error tampil di dalam dialog dengan "Coba hapus lagi"; 404 dianggap sudah terhapus.
- **Perbaikan bersama:** `useModalDialog` (buka modal dan kembalikan fokus) dipakai ConfirmDialog dan form. Judul ConfirmDialog kini memakai `useId`, karena sebelumnya dialog keluar dan dialog hapus berbagi id `confirm-title`. `lib/products-api.js` memvalidasi bentuk respons.

## Bukti selesai

Verifikasi pada 15 Oktober 2026 dengan build produksi (`npm start`, port 3051, database sementara) di Google Chrome headless melalui Playwright (`playwright-core` dari cache npx, di luar repo). Tidak ada dependency atau file uji di repo.

- **Daftar** (1280px, pemilik): 9 baris dengan foto lokal. Pastry → Butter Croissant dan Cinnamon Roll. Cari `latte` → 3 menu. Cari `%` → "Tidak ada menu yang cocok…".
- **Tambah:**
  - Simpan form kosong → error Nama dan Harga, fokus ke `product-name`, 0 request.
  - Pilih Pastry → foto Croissant/Cinnamon roll dengan Croissant terpilih. Petunjuk harga "Tampil sebagai Rp 15.000".
  - Nama `<img src=x onerror=alert(1)>`, stok 0, label Baru → POST tersimpan, pesan sukses tampil, nama tampil literal, 0 elemen `img[src=x]`, 0 alert, dan pill "Habis".
- **Edit** Americano: form terisi (22000/40). Harga 25000 → body PATCH `{"price":25000}`. Ganti kategori ke Non-kopi → foto Matcha. Escape menutup tanpa menyimpan dan fokus kembali ke "Edit Americano".
- **Hapus** Butter Croissant: dialog "Hapus Butter Croissant?". Escape membatalkan; konfirmasi → pesan sukses, 9 baris.
- **Refresh:** 9 baris, Americano Rp 25.000, croissant tidak ada. `GET /api/products` mengembalikan `Americano:25000:40` dan `<img src=x onerror=alert(1)>:15000:0`.
- **Error** (360px):
  - 400 dari server dengan `fields.name` → pesan di field Nama, `aria-invalid="true"`, tanpa notice umum.
  - 500 → "Produk belum tersimpan | Permintaan belum bisa diproses. | Kode permintaan: r-500"; nilai form tetap dan tombol aktif. Simpan ulang berhasil.
  - DELETE offline → error di dalam dialog, tombol "Coba hapus lagi"; coba lagi menghapus.
  - GET gagal saat filter → "Daftar belum diperbarui" dengan tabel lama tetap; coba lagi → 4 menu Kopi.
- **Sesi dicabut** di SQLite saat form terbuka, lalu simpan → 401 → `/masuk?lanjut=/produk` dengan pesan "Sesi tidak lagi berlaku…".
- **Kasir** `/produk` → halaman 403; tombol Tambah 0, tombol Edit 0, menu Produk tidak ada.
- **Responsif:** 360, 768, dan 1280px tanpa overflow halaman maupun tabel. Tombol "Edit Cappuccino" terlihat tanpa geser di ketiga lebar; di 360px tidak ada sel kartu yang bertumpuk.
- Tidak ada `pageerror`. Log API tanpa error 500. Seluruh skenario CRUD dan error diulang pada database baru setelah perubahan CSS terakhir dan tetap lolos.
- `npm run check` (lint termasuk batas 25 baris, format, build) dan `git diff --check` lolos.

## Review dan verifikasi ulang

Review pada 15 Oktober 2026 dengan Chrome headless/Playwright, build produksi Express, port acak, dan database sementara. Desain diperiksa dengan panduan `frontend-design` dan DESIGN.md. Tidak menambah unit test atau dependency proyek.

- **Form saat menyimpan:** sebelumnya kolom masih bisa diubah ketika request berjalan sehingga perubahan baru bisa hilang saat dialog ditutup. Sekarang seluruh kolom dan foto dikunci dalam fieldset selama penyimpanan; submit ulang dan Escape diblokir sampai request selesai. Setelah gagal, kolom aktif lagi dan nilainya tetap.
- **Validasi server:** error field mengembalikan fokus ke field pertama yang salah setelah DOM diperbarui. Pesan field non-string ditampilkan sebagai error umum yang aman, bukan membuat React crash. Validasi teks klien menolak karakter kontrol dan surrogate tak berpasangan seperti server; batas dihitung per karakter Unicode.
- **Respons produk/foto rusak:** objek pada `tag` atau preset `null` sebelumnya membuat halaman kosong. Validasi kini memeriksa kategori, harga/stok, foto lokal, label, dan isi katalog/default. Delapan respons rusak mendapat pesan "Respons server tidak valid" dengan retry; tidak ada `pageerror`.
- **Aksesibilitas daftar:** `aria-busy` sekarang hanya aktif ketika request berjalan. Setelah filter gagal, error dapat diumumkan dan tabel lama tetap tersedia untuk retry.
- **CRUD nyata:** daftar seed, kategori, pencarian debounce, pencarian `%`, tambah markup sebagai teks, stok 0, nama 60 emoji, edit, hapus, refresh, dan restart API lolos. Batas angka/teks invalid ditolak klien tanpa request. Pratinjau harga dengan nol di depan sesuai nominal yang disimpan.
- **Stok selama edit:** Americano dibuka dengan stok 40, lalu checkout nyata mengurangi 2 unit ketika form masih terbuka. Simpan harga mengirim hanya `{"price":25000}`; stok tetap 38, bukan tertimpa 40. Edit tanpa perubahan tidak mengirim PATCH. Ganti kategori/foto hanya mengirim field tersebut.
- **Snapshot struk:** harga struk checkout tetap 22.000 setelah harga menu diubah ke 25.000. Hapus Butter Croissant mempertahankan seluruh item snapshot serta omzet; hanya referensi produk menjadi `null`.
- **Error/retry:** 400 memfokuskan Nama dan mengatur `aria-invalid`; 500 mempertahankan nilai dan retry berhasil. Hapus offline bisa diulang; produk yang dihapus dari luar lalu mendapat 404 dianggap selesai. GET gagal mempertahankan baris dan retry memuat kategori yang benar.
- **Sesi/peran:** sesi dicabut saat form terbuka menyebabkan 401 dan redirect ke `/masuk?lanjut=/produk` tanpa perubahan produk. Kasir tidak melihat kontrol pengelolaan dan API POST produk tetap menolak dengan 403.
- **Visual/keyboard:** foto berasal dari bundle lokal; halaman, tabel, dan form muat pada 360/768/1280px tanpa overflow horizontal. Escape membatalkan ketika tidak sibuk; fokus kembali ke tombol pemicu. Screenshot desktop dan form error mobile diperiksa secara visual. Judul dialog hapus unik.
- Regresi POS-006 (login, refresh, role switch, logout/error modal, 401/403, redirect aman, dan keyboard) tetap lolos setelah perubahan hook modal/API bersama.
- `integrity_check`/`foreign_key_check`, `npm run check`, serta aturan fungsi maksimal 25 baris lolos. Tidak ada alert XSS, error JavaScript browser, atau error 500 nyata dari server; respons gagal di browser sengaja disimulasikan untuk memeriksa retry.

Batas tahap ini:

- Halaman memuat ulang daftar setelah mutasi dan tidak memakai pembaruan optimistis. Perubahan dari tab lain baru terlihat setelah filter berubah atau halaman dimuat ulang.
- Saat filter gagal dimuat, tombol kategori sudah aktif tetapi tabel masih menampilkan data sebelumnya bersama pesan error.
- Fokus setelah menghapus kembali ke dokumen, karena tombol pemicunya ikut hilang bersama baris.
- Firefox dan Safari belum diuji.
