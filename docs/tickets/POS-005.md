# POS-005 — API checkout dan transaksi atomik

Status: Belum dimulai
Prioritas: P0
Dependensi: POS-004

## Tujuan

Server menghitung harga/subtotal/diskon/kembalian dan menyimpan penjualan beserta stok dalam satu transaksi SQLite.

## Kriteria penerimaan

- [ ] POST /api/transactions menerima produk/jumlah, diskon, pelanggan, metode, dan idempotency key.
- [ ] Total/harga/peran dari client tidak dipercaya; server menghitung memakai harga DB terkini.
- [ ] Stok dicek dan dikurangi atomik; kegagalan satu item membatalkan seluruh transaksi.
- [ ] Uang kurang, qty tidak valid, produk dihapus, diskon di luar 0–100%, dan stok kurang ditolak.
- [ ] Replay key yang sama dengan payload sama mengembalikan transaksi yang sama; payload beda mendapat 409.
- [ ] GET daftar/detail transaksi dibatasi workspace; item dan pengaturan struk disnapshot.

## Verifikasi tanpa unit test

1. Coba contoh PRD: 2 kopi + croissant, diskon 10%, bayar Rp100.000 menghasilkan total Rp72.000/kembalian Rp28.000.
2. Kirim dua checkout untuk stok terakhir: hanya satu berhasil.
3. Ulangi request dengan key sama; stok dan jumlah transaksi tidak berubah dua kali.
4. Coba satu item kehabisan stok; item lain juga tidak berkurang.
