## Perubahan

**Keamanan demo (server):**

- `middleware/origin-check.js`: POST/PATCH/DELETE dengan `Origin` asing, atau tanpa `Origin` tetapi `Sec-Fetch-Site: cross-site`/`same-site`, ditolak 403 `ORIGIN_REJECTED`. Origin tambahan bisa diizinkan lewat `ALLOWED_ORIGINS`. Ini lapisan kedua setelah cookie `SameSite=Strict` dan body wajib JSON.
- `middleware/rate-limit.js` (fixed window per IP, di memori proses): `API_RATE_LIMIT` per menit untuk semua `/api` (default 300), dan `DEMO_SESSION_LIMIT` per 10 menit untuk `POST /api/demo/sessions` (default 30). Melebihi batas → 429 `RATE_LIMITED` dengan `Retry-After`.
- Kapasitas `DEMO_MAX_WORKSPACES` (default 500): ruang demo baru saat penuh → 503 `DEMO_CAPACITY`, setelah ruang demo kedaluwarsa dibersihkan. Ganti peran pada ruang demo yang ada tetap diizinkan.
- `middleware/security-headers.js`:
  - CSP dengan `script-src 'self'`. Gaya inline diizinkan untuk tinggi grafik dan prototype; font Google; `frame-ancestors 'none'`.
  - `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, COOP, dan `Permissions-Policy`; HSTS saat HTTPS.
  - Diterapkan juga ke React build dan prototype.
- `app.js` dipecah: `mountApiGuards`, `mountApiRoutes`, dan `mountStatic`.

**Perbaikan yang ditemukan saat integrasi:**

- **Mode dev rusak oleh pemeriksaan origin:** bentuk singkat proxy Vite memakai `changeOrigin: true`, sehingga `Host` menjadi `127.0.0.1:API` dan semua mutasi browser lewat `npm run dev` mendapat 403. `client/vite.config.js` kini memakai `changeOrigin: false` untuk `/api` dan `/prototype`.
- **Skenario PRD "tambah melebihi stok":** penjelasan sebelumnya hanya `title` tooltip. Kini terlihat di kartu menu ("Stok 8 · semua sudah di pesanan") dan di baris pesanan ("Sudah mencapai stok (8)").

**Dokumentasi:**

- PRD ditulis ulang menjadi v2.0 fullstack. Isinya sesi/peran demo, data di SQLite per ruang demo, keamanan, dan non-fungsional yang sesuai, serta kriteria penerimaan tambahan untuk dua pengunjung. PRD prototype tetap di `dist/prd.html`.
- README memuat ringkasan fitur, batasan demo, tabel konfigurasi, keamanan, dan struktur.
- API.md: bagian "Keamanan dan batas" (kode 403/413/415/429/503 dan header), dan seluruh endpoint ditandai aktif.
- `.env.example` memuat variabel baru. Checklist POS-012 di VERIFICATION.md diisi.

**Skenario PRD bagian 10** (dua pengunjung: A kasir, lalu ganti ke pemilik; B pemilik di ruang demo lain; CSP aktif):

1. 2 Kopi Susu Seduh + 1 Butter Croissant, diskon 10% → "Subtotal Rp 80.000 · Diskon − Rp 8.000 · Total pembayaran Rp 72.000".
2. Bayar Rp100.000 → struk "Total Rp 72.000 | Kembalian Rp 28.000"; stok kopi 35→33 dan croissant 18→17.
3. Uang Rp50.000 → "Uang kurang Rp 22.000." dengan konfirmasi nonaktif; jumlah transaksi tetap 30 sebelum bayar.
4. QRIS → struk "Metode QRIS (simulasi)", tanpa elemen gambar/canvas QR.
5. Cinnamon Roll (stok 8) ditambah 8× → tombol tambah nonaktif, kartu "Stok 8 · semua sudah di pesanan", dan pesanan "Sudah mencapai stok (8)".
6. Tab baru (cookie sama) → riwayat 32 transaksi dengan transaksi terbaru di atas.
7. Harga Kopi Susu Seduh diubah ke Rp35.000 → struk lama tetap "2 × Rp 28.000 = Rp 56.000".
8. Laporan "Hari ini" 2 transaksi → CSV `seduh-laporan-2026-10-15-sampai-2026-10-15.csv` berisi 2 baris; nama pelanggan markup tersimpan sebagai teks.
9. Reset → Batal: transaksi tetap 32. Konfirmasi → kembali 30 transaksi dan harga kopi Rp28.000.
10. Nama pelanggan `<b>Raka</b>` tampil literal di struk, dengan 0 elemen `<b>`.

**Isolasi:** B tetap 30 transaksi, pencarian nomor transaksi A di B → 0, dan stok kopi B tetap 35. Tanpa error console (selain log jaringan 401 `GET /api/session` di halaman masuk), tanpa pelanggaran CSP, dan tanpa respons 5xx.

## Review dan perbaikan — 15 Oktober 2026

- **Origin kanonis:** sebelumnya `Host: LOCALHOST:80` dengan `Origin: http://localhost`, serta allowlist `https://Allowed.Example:443/` dengan header `https://allowed.example`, ditolak 403. Sekarang HTTP(S), host, dan port bawaan dinormalisasi. Konfigurasi origin invalid ditolak saat startup; origin asing/opaque tetap ditolak.
- **Memori limiter:** sebelumnya jumlah IP bisa terus bertambah dan seluruh map dipindai pada setiap request setelah 10.000 entri. Sekarang setiap limiter menyimpan paling banyak 10.000 IP, cleanup paling sering sekali per detik saat diperlukan, dan IP baru ditolak sementara ketika penuh. Entri aktif tidak digusur, sehingga hitungan IP lama tidak dapat direset dengan memenuhi map.
- **Login yang menunggu kunci:** ketika workspace berakhir saat request role switch menunggu SQLite, server sebelumnya mengirim 201 tetapi cookie barunya langsung mendapat 401. Waktu dan sesi sekarang dibaca ulang di dalam transaksi setelah kunci diperoleh; workspace kedaluwarsa diganti dengan ruang baru sesuai kapasitas.
- **Dokumentasi kapasitas:** jumlah workspace berasal dari SQLite, bukan memori. Batas tetap berlaku setelah restart dan dibaca atomik oleh proses API yang berbagi database.

Verifikasi review memakai HTTP aktual, SQLite/port sementara, build produksi dan Chrome melalui Playwright, tanpa unit test atau dependency baru:

- Origin sendiri/configured yang dinormalisasi diterima. Origin asing, `null`, serta Fetch Metadata cross-site/same-site ditolak. PATCH dari origin asing tidak mengubah pengaturan. Tujuh konfigurasi origin invalid menggagalkan startup.
- Serangan browser dari port lain (cookie sama, POST no-cors) mendapat 403 dan peran sesi tidak berubah. Login serta checkout lewat Vite dengan Host dipertahankan tetap berhasil; origin asing via proxy tetap 403.
- CSP/header keamanan diperiksa pada React, API, prototype, aset, dan fallback. Prototype membuka menu/pembayaran; tidak ada pelanggaran CSP produksi. HSTS dan cookie Secure hanya muncul pada HTTPS melalui proxy yang dipercaya; header HTTPS palsu pada mode tanpa trust diabaikan.
- Body 120 KB → 413, JSON rusak → 400, charset invalid → 415. Batas API dan login mendapat 429 serta Retry-After; IP lain tetap mendapat kuota sendiri, dan X-Forwarded-For palsu tanpa proxy dipercaya tidak memisahkan kuota.
- 10.000 IP berbeda melalui HTTP diterima; IP ke-10.001 ditolak 429 dan IP awal tetap dibatasi. Setelah menunggu jendela satu menit yang sebenarnya (tanpa clock palsu), entri kedaluwarsa membebaskan slot; kuota kembali berlaku dan hit berikutnya mendapat 429.
- Kapasitas 2 tetap menolak workspace ketiga setelah restart; role switch tetap berjalan tanpa memperpanjang expiry. Logout dan cleanup workspace kedaluwarsa membebaskan slot. Delapan login bersamaan pada dua API/database yang sama dengan kapasitas 3 menghasilkan tepat tiga 201 dan lima 503.
- Login yang menunggu kunci sampai expiry membuat workspace baru, menghapus yang berakhir, tetap satu workspace pada kapasitas 1, dan cookie baru mendapat 200 di GET sesi.
- Penjelasan stok penuh terlihat pada kartu/baris pesanan. Enam halaman diperiksa pada 360/768/1280px tanpa overflow. Keyboard dialog, reduced motion, dan isolasi struk pada mode print lolos, tanpa pageerror atau pelanggaran CSP.
- Regresi POS-006 sampai POS-011 dijalankan pada batas rate bawaan dan lolos. Uji rollback POS-011 menghasilkan satu kegagalan yang sengaja dipicu pada database sementara.
- Audit dependency produksi (`npm audit --omit=dev`) melaporkan 0 kerentanan pada waktu pemeriksaan. Proxy npm yang tidak dapat di-resolve dilewati hanya lewat opsi perintah, tanpa mengubah konfigurasi pengguna atau dependency.
- `npm run check` (lint maksimal 25 baris per fungsi, format, build) dan `git diff --check` lolos. Tidak ada deployment; proses API lama PID 36173 tidak disentuh.
