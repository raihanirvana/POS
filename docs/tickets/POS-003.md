# POS-003 — Sesi demo dan hak akses

Status: Selesai
Prioritas: P0
Dependensi: POS-002

## Tujuan

Masuk sebagai pemilik/kasir melalui sesi server dan cookie HttpOnly; setiap kunjungan demo baru memiliki ruang data sendiri.

## Kriteria penerimaan

- [x] POST /api/demo/sessions membuat ruang demo dan seed terisolasi; peran divalidasi.
- [x] GET /api/session dan DELETE /api/session mendukung masuk/keluar serta sesi kedaluwarsa.
- [x] Token acak disimpan sebagai hash; cookie HttpOnly, SameSite, dan Secure saat HTTPS.
- [x] Middleware membedakan pemilik/kasir; identitas workspace berasal dari sesi server.
- [x] Sesi tidak menerima workspace_id/peran yang dikirim sebagai otorisasi bebas dari frontend.
- [x] Pemilik/kasir adalah login demo tanpa password, bukan klaim autentikasi akun produksi.

## Verifikasi tanpa unit test

1. Gunakan dua cookie jar curl dan buktikan ruang data berbeda.
2. Tanpa cookie dapat 401; kasir mengakses endpoint pemilik mendapat 403.
3. Logout dan kadaluwarsa sesi menyebabkan API terlindungi menolak akses.

## Implementasi

- `server/services/demo-session-service.js`: buat ruang demo + seed + sesi dalam satu transaksi, ganti peran pada workspace yang sama, validasi token, dan logout.
- `server/middleware/auth.js`: `loadSession` membaca cookie dan tabel `sessions`; `requireSession` (401) dan `requireRole(...)` (403) dipakai endpoint fitur berikutnya.
- `server/lib/session-cookie.js`, `server/validation/session-validation.js`, `server/repositories/`, `server/routes/session.js`, `server/lib/http-error.js`.
- Konfigurasi baru `DEMO_TTL_MINUTES` (default 720) dan `TRUST_PROXY` (default false; `true` ditolak). Semua respons `/api` memakai `Cache-Control: no-store`.

## Bukti selesai

Verifikasi selesai pada 14 Oktober 2026 dengan Node 22.20.0, memakai database sementara dan port 3012–3014 sehingga `data/seduh.sqlite` tidak tersentuh.

- Dua cookie jar: A masuk `owner`, B masuk `cashier`, keduanya 201 dengan `workspaceCreated: true`. SQLite menunjukkan dua workspace berbeda, masing-masing 9 produk dan 35 transaksi. `GET /api/session` mengembalikan peran masing-masing.
- Cookie: `seduh_session=<43 karakter>; Path=/api; Expires=…; HttpOnly; SameSite=Strict`. Tidak ada baris `sessions.token_hash` yang sama dengan token cookie; panjang hash 64.
- `Secure`: dengan `TRUST_PROXY=loopback` dan `X-Forwarded-Proto: https` cookie mendapat `Secure`; HTTP biasa tidak. Tanpa `TRUST_PROXY`, header `X-Forwarded-Proto: https` palsu tidak menambahkan `Secure`.
- 401/403: tanpa cookie → 401 `UNAUTHENTICATED`. Endpoint pemilik belum ada sebelum POS-004, jadi harness sementara di scratchpad (di luar repo) memasang `requireSession` + `requireRole('owner')` asli pada database yang sama: tanpa cookie 401, owner 200, cashier 403 `FORBIDDEN`. Cashier dengan header `X-Role: owner` dan query `?role=owner&workspaceId=…` tetap 403.
- Validasi body (semuanya 400, jumlah workspace tidak bertambah): `role: "admin"`, body dengan `workspaceId`, body dengan `__proto__`, array, `text/plain`, tanpa body. JSON rusak → 400 `INVALID_JSON` dengan `no-store`.
- Ganti peran: B (cashier) POST `owner` → 201 `workspaceCreated: false`, workspace ID sama, sesi cashier punya `revoked_at`, `expiresAt` tidak diperpanjang. Cookie lama B → 401 dan cookie dihapus; cookie baru B → 200 pada rute pemilik.
- Logout: DELETE → 204 dan cookie dihapus. Cookie lama A → 401. Data workspace A terhapus seluruhnya; workspace B tetap 35 transaksi. DELETE tanpa cookie → 204.
- Cookie rusak (`abc`) dan token berformat benar tetapi tidak dikenal → 401 dan cookie dihapus.
- Kedaluwarsa: `expires_at` sesi diubah ke masa lalu → `GET /api/session` dan rute pemilik 401 `SESSION_EXPIRED` dengan cookie dihapus. Dengan `DEMO_TTL_MINUTES=1` tanpa mengubah database: t+0 → 200; t+62 detik curl tidak mengirim cookie lagi karena `Expires` lewat (401 `UNAUTHENTICATED`); token lama yang dikirim manual → 401 `SESSION_EXPIRED`.
- Pembersihan: workspace yang kedaluwarsa dihapus saat login baru membuat workspace (tersisa 1 workspace, 35 transaksi).
- Restart API: sesi B tetap 200 setelah proses API dihentikan dan dijalankan ulang.
- Lima login bersamaan: semua 201, menghasilkan workspace terpisah; setiap workspace tepat 35 transaksi. `foreign_key_check` kosong, `integrity_check` ok.
- Config: `TRUST_PROXY=true`, `DEMO_TTL_MINUTES=0`, dan `DEMO_TTL_MINUTES=abc` ditolak saat startup.
- `npm run check`: lint, format, dan build lolos.

## Review dan perbaikan

Review pada 14 Oktober 2026 mempertahankan keputusan ganti peran di workspace yang sama dan kebijakan logout 204. Bug yang diperbaiki:

- Logout menggunakan snapshot sesi dari middleware tanpa pemeriksaan ulang. Jika rotasi token sudah mencabut sesi itu saat logout menunggu kunci tulis, workspace sesi baru masih dapat terhapus. Sekarang sesi dicabut secara bersyarat di dalam transaksi; hanya sesi yang masih aktif dapat menghapus workspace.
- Charset dan content encoding yang tidak didukung dikembalikan sebagai 500. Keduanya sekarang mendapat 415 `UNSUPPORTED_MEDIA_TYPE`, tetap dengan `Cache-Control: no-store`.
- Angka hop `TRUST_PROXY` di luar bilangan bulat aman dapat diterima. Konfigurasi tersebut sekarang ditolak saat startup.

Verifikasi tambahan menggunakan database/port sementara, tanpa file unit test di repo:

- Regresi POS-002: migrasi baru/ulang, upgrade versi 1, rollback, seed idempoten, snapshot, isolasi workspace, constraint, indeks, integritas, dan empat proses migrasi bersamaan semuanya lolos. Tidak ada perubahan pada kedua file migrasi yang sudah diterapkan.
- Regresi logout melalui HTTP nyata: writer SQLite melakukan rotasi sesi, sementara request DELETE sudah membaca sesi lama dan menunggu kunci tulis. Setelah writer commit, DELETE tetap 204, sesi pengganti tetap 200, dan omzet workspace tidak berubah.
- Dua login mempunyai workspace berbeda dan hash token tersimpan di DB. Ganti peran mempertahankan workspace serta waktu kedaluwarsa, dan cookie lama tidak bisa membaca sesi.
- Validasi body, cookie salah/tidak dikenal, 400 JSON rusak, dan 415 charset/encoding semuanya lolos. Tidak ada workspace tambahan dari body yang ditolak.
- Middleware asli diuji pada rute sementara di luar repo: anonim 401, pemilik 200, kasir 403 meski mengirim header/query yang mengaku sebagai pemilik atau workspace lain.
- Logout aktif menghapus data miliknya, logout tanpa sesi tetap 204, expiry menghapus cookie, dan login baru membersihkan workspace kedaluwarsa. Sesi valid tetap bisa digunakan setelah restart API.
- Lima login bersamaan menghasilkan lima workspace terpisah. Cookie Secure hanya muncul untuk HTTPS melalui proxy yang dipercaya; header palsu saat trust proxy false tidak menambahkannya.
- `TRUST_PROXY=true`, angka hop yang tidak aman, serta angka yang menjadi Infinity ditolak. `PRAGMA integrity_check` ok dan `foreign_key_check` kosong.
- `npm run check` lolos (lint, format, build), termasuk aturan 25 baris per fungsi. Seluruh verifikasi memakai data sementara.

Batas tahap ini: belum ada endpoint fitur yang memakai `requireRole`. Uji 403 diulang dengan endpoint pemilik nyata di POS-004. Ganti peran adalah fitur demo, jadi kasir dapat menjadi pemilik pada ruang demonya sendiri; tetapi tidak bisa menjangkau workspace lain. Rate limit login demo dan pemeriksaan origin/CSRF ditangani POS-012 (saat ini `SameSite=Strict` dan body wajib JSON). UI masuk/keluar dikerjakan POS-006.
