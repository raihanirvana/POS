# POS-003 — Sesi demo dan hak akses

Status: Belum dimulai
Prioritas: P0
Dependensi: POS-002

## Tujuan

Masuk sebagai pemilik/kasir melalui sesi server dan cookie HttpOnly; setiap kunjungan demo baru memiliki ruang data sendiri.

## Kriteria penerimaan

- [ ] POST /api/demo/sessions membuat ruang demo dan seed terisolasi; peran divalidasi.
- [ ] GET /api/session dan DELETE /api/session mendukung masuk/keluar serta sesi kedaluwarsa.
- [ ] Token acak disimpan sebagai hash; cookie HttpOnly, SameSite, dan Secure saat HTTPS.
- [ ] Middleware membedakan pemilik/kasir; identitas workspace berasal dari sesi server.
- [ ] Sesi tidak menerima workspace_id/peran yang dikirim sebagai otorisasi bebas dari frontend.
- [ ] Pemilik/kasir adalah login demo tanpa password, bukan klaim autentikasi akun produksi.

## Verifikasi tanpa unit test

1. Gunakan dua cookie jar curl dan buktikan ruang data berbeda.
2. Tanpa cookie dapat 401; kasir mengakses endpoint pemilik mendapat 403.
3. Logout dan kadaluwarsa sesi menyebabkan API terlindungi menolak akses.
