# POS-004 — API produk dan stok

Status: Selesai
Prioritas: P0
Dependensi: POS-003

## Tujuan

Implementasi daftar/pencarian produk dan CRUD pemilik dengan validasi server dan repository SQLite.

## Kriteria penerimaan

- [x] GET /api/products mendukung kategori/pencarian; POST/PATCH/DELETE dibatasi pemilik.
- [x] Nama, kategori, harga integer, stok integer, dan panjang deskripsi divalidasi.
- [x] Query diparameterisasi dan selalu dibatasi workspace sesi.
- [x] Hapus menu tidak menghapus snapshot struk lama; kategori foto preset disediakan.
- [x] Error 400/404/403 konsisten dan mutasi tidak bocor ke ruang demo lain.

## Verifikasi tanpa unit test

1. Curl CRUD valid/invalid, stok nol, akses kasir, dan ID milik workspace lain.
2. Restart API dan periksa produk tetap tersimpan.

## Implementasi

- `server/routes/products.js`: GET untuk kasir/pemilik, POST/PATCH/DELETE hanya pemilik (`requireRole('owner')`). Workspace selalu dari `request.auth`.
- `server/validation/product-validation.js` dan `server/validation/common.js`: validasi tipe dan batas, field asing ditolak, panjang dihitung per karakter Unicode (sama dengan `length()` SQLite), dan karakter kontrol ditolak.
- `server/services/product-service.js`: aturan foto preset per kategori, 404 untuk produk yang tidak ada di workspace, dan update dalam transaksi.
- `server/repositories/product-repository.js`: semua query memakai parameter dan `workspace_id`. Nama kolom UPDATE hanya dari daftar tetap. Pola LIKE di-escape.
- `server/lib/product-catalog.js`: kategori, 8 preset foto beserta kategorinya, dan foto default per kategori. Katalog ikut dikirim pada `GET /api/products`.
- `HttpError` sekarang bisa membawa `fields` (pesan per field) untuk form POS-007.

## Bukti selesai

Verifikasi pada 15 Oktober 2026 dengan Node 22.20.0, memakai database sementara dan port 3021 sehingga `data/seduh.sqlite` tidak tersentuh. Sesi: pemilik A, pemilik B (workspace lain), dan kasir C.

- Tanpa cookie → 401. Pemilik A → 9 produk seed sesuai urutan prototype, katalog berisi 3 kategori dan 8 preset.
- Filter: `category=Pastry` → 2 produk; `search=latte` → 3; `search=susu` juga cocok dengan deskripsi (4); `category=Kopi&search=LATTE` → Caffè Latte. `search=%`, `search=_`, dan `' OR 1=1 --` → 0 hasil. `workspaceId` di query diabaikan. Kategori asing, kategori ganda, dan kata kunci 61 karakter → 400 dengan `fields`.
- POST valid → 201; nama di-trim; tanpa `imageKey` mendapat `latte`. Stok 0 dengan tag dan preset sesuai → 201. Nama berisi markup disimpan dan dikembalikan sebagai teks JSON.
- POST invalid → 400 dengan `fields`:
  - foto preset di luar kategori;
  - nama kosong, kategori asing, harga 999, stok −1, deskripsi 101 karakter (lima pesan sekaligus);
  - harga berupa string, stok pecahan;
  - harga pecahan, stok 100.001;
  - nama 61 karakter, harga 10.000.001;
  - field `workspaceId`/`id`/`seedKey`;
  - nama dengan karakter NUL;
  - tag 31 karakter;
  - field wajib yang tidak dikirim.
  - Body array dan `text/plain` juga ditolak 400.
- PATCH harga+stok → 200 dengan `updatedAt` baru. Kategori Kopi → Non-kopi tanpa foto → foto berubah ke `matcha`; `imageKey: "tea"` + `tag: null` → 200; `americano` untuk Non-kopi → 400. Body kosong → 400, stok −5 → 400, UUID tidak dikenal dan ID rusak → 404.
- Kasir C: GET 200; POST, PATCH, dan DELETE → 403 `FORBIDDEN`, juga dengan header `X-Role: owner`. Produk tidak berubah di SQLite.
- Pemilik B: PATCH dan DELETE produk milik A → 404. Daftar B tidak memuat produk A; produk A tetap Rp34.000.
- Hapus Kopi Susu Seduh di A (terjual di 7 item, total Rp224.000) → 204. Sesudahnya 7 item tetap ada dengan total sama, `product_id` NULL, dan omzet A tidak berubah. Hapus ulang → 404. Workspace lain tetap memiliki produk itu.
- Restart API: daftar produk A identik sebelum dan sesudah restart (11 produk termasuk produk baru dan stok 0).
- `PRAGMA foreign_key_check` kosong, `integrity_check` ok, log API tanpa error 500.
- `npm run check`: lint, format, dan build lolos. `git diff --check` lolos.

## Review dan perbaikan

Review pada 15 Oktober 2026 menemukan dua bug yang diperbaiki:

- Mutasi memakai otorisasi yang dibaca middleware sebelum menunggu transaksi. PATCH tertunda tetap mengubah harga sesudah token pemilik dicabut saat pergantian peran. `withOwnerWorkspace` kini memeriksa ulang sesi/workspace/peran dan kedaluwarsa di dalam transaksi untuk POST/PATCH/DELETE. Pembuatan produk dan pembacaan hasilnya juga berada dalam transaksi yang sama. Token lama yang ditolak mendapat 401 dan cookie dihapus.
- Unicode dengan surrogate tidak berpasangan diterima lalu berubah menjadi karakter pengganti saat disimpan UTF-8. Kontrol C1 seperti U+0085 juga diterima meskipun kontrak melarang karakter kontrol. Validasi teks sekarang menolak keduanya, tanpa menolak pasangan surrogate/emoji yang valid.

Verifikasi review pada API dan database sementara, tanpa unit test di repo:

- Sebelum perbaikan, PATCH yang menunggu writer SQLite setelah rotasi token menghasilkan 200 dan mengubah harga Rp28.000 menjadi Rp99.000. Setelah perbaikan, hasilnya 401 dan harga tetap Rp28.000.
- POST, PATCH, dan DELETE yang tertunda pada skenario yang sama masing-masing ditolak 401, cookie lama dihapus, daftar produk tidak berubah, dan sesi pengganti kasir tetap dapat GET produk.
- CRUD, foto default saat kategori berubah, foto pilihan, tag null, stok nol, dan field errors lolos. Dua puluh dua body tidak valid ditolak tanpa menambah produk, termasuk surrogate tunggal, kontrol C1, field asing, dan batas angka/panjang.
- Nama 60 emoji valid tersimpan tanpa perubahan; 61 emoji ditolak. Pola pencarian persen, underscore, backslash, dan kutip diperlakukan sebagai teks literal, termasuk ketika ada produk yang benar-benar memuat karakter tersebut.
- Endpoint pemilik nyata menolak kasir dengan 403 meski ada header X-Role palsu. PATCH/DELETE pemilik B atas produk A tetap 404. Snapshot nama/harga/total item dan omzet tidak berubah setelah menu diedit/dihapus.
- Daftar produk identik setelah restart. Pemeriksaan foreign key dan integrity check lolos.
- Regresi POS-003 (sesi, logout tertunda, ganti peran, expiry, cookie/proxy, isolasi, restart, login bersamaan) lolos setelah resolver sesi digunakan ulang.
- `npm run check` lolos, termasuk batas 25 baris per fungsi. Semua proses verifikasi dihentikan; `data/seduh.sqlite` tidak dipakai.

Batas tahap ini:

- Pencarian tidak peka huruf besar/kecil hanya untuk huruf ASCII. `caffe` tidak menemukan `Caffè`.
- Nama produk boleh sama dalam satu workspace.
- PATCH stok menimpa nilai (last write wins). Pengurangan stok atomik saat checkout dikerjakan POS-005.
- Uji 403 di POS-003 yang sebelumnya memakai harness kini diulang dengan endpoint pemilik nyata.
- UI produk dikerjakan POS-007.
