# POS-006 — Shell React dan masuk demo

Status: Selesai
Prioritas: P0
Dependensi: POS-003

## Tujuan

Port layout Seduh ke komponen React kecil, routing halaman, sesi, dan pilihan peran demo.

## Kriteria penerimaan

- [x] Tampilan mengikuti DESIGN.md dan skill frontend-design; sidebar/header responsif.
- [x] Pengunjung dapat masuk sebagai pemilik atau kasir dan keluar.
- [x] Sesi dimuat saat refresh; route terlindungi dan menu mengikuti peran.
- [x] API client punya penanganan 401/403, loading/error/retry; cookie tidak ditaruh di localStorage.
- [x] Setiap komponen/fungsi <=25 baris tanpa pemadatan JSX.

Catatan desain: implementasi awal mengikuti DESIGN.md dan prototype (`dist/`, `screenshots/`) karena skill `frontend-design` belum tersedia pada sesi tersebut. Saat review, skill tersebut tersedia dan dipakai untuk memeriksa konsistensi tampilan: token warna, Plus Jakarta Sans, sidebar 216px, breakpoint 1190/950/720px, radius tombol/input 10px, tanpa animasi masuk, fokus terlihat, dan reduced motion.

## Implementasi

- **Router kecil** (`client/src/lib/router.js`) memakai History API dan `useSyncExternalStore`, tanpa dependency baru. Express dan Vite sudah mengembalikan `index.html` untuk path aplikasi.
- **Route** (`lib/routes.js`): `/masuk`, `/kasir`, `/dashboard`, `/produk`, `/transaksi`, `/laporan`, `/pengaturan`. Kasir: Kasir dan Transaksi. Pemilik: semua menu, sesuai hak akses API.
  - Tanpa sesi diarahkan ke `/masuk?lanjut=…`.
  - `lanjut` hanya menerima route yang dikenal dan diizinkan untuk peran itu; nilai lain kembali ke `/kasir` sehingga tidak ada open redirect.
  - Route di luar peran menampilkan halaman 403, dan path tak dikenal menampilkan 404 di dalam shell.
- **API client** (`lib/api.js`):
  - `ApiError` membawa `status`, `code`, `fields`, dan `requestId`.
  - Error jaringan dan respons non-JSON mendapat pesan yang ramah.
  - Setiap 401 memberi tahu `useSessionState`, yang mengosongkan sesi hanya jika sebelumnya masuk.
  - Token tidak pernah dibaca atau disimpan JavaScript karena cookie bersifat HttpOnly.
- **Sesi** (`hooks/useSessionState.js`, `session/`): muat sesi saat start (loading/error/retry), masuk, ganti peran (workspace sama), dan keluar. Pesan ditampilkan di halaman masuk untuk sesi kedaluwarsa, sesi tidak dikenali, dan setelah keluar.
- **Shell:**
  - Sidebar: brand, chip ruang demo dengan waktu kedaluwarsa WIB, menu per peran, panduan PRD, catatan demo, dan profil.
  - Topbar: breadcrumb, badge demo, tanggal, tombol ganti peran, serta tombol keluar dengan dialog `<dialog>` konfirmasi.
  - Lainnya: skip link, fokus pindah ke `main` saat ganti halaman, `document.title` per halaman, dan item menu aktif digulir agar terlihat di ponsel.
- **Halaman fitur** masih placeholder jujur: label "Belum tersedia · POS-00X", rencana isi, dan tautan ke rancangan prototype. Halaman itu tidak dianggap selesai.
- **Komponen fondasi POS-001 dihapus:** halaman health, ProjectIntro, StackOverview, dan useHealth. `GET /api/health` tetap ada di server.

## Bukti selesai

Verifikasi pada 15 Oktober 2026. Build produksi dijalankan dengan `npm start` (`NODE_ENV=production`, port 3041, database sementara) dan diuji di Google Chrome headless melalui Playwright. `playwright-core` 1.63 diambil dari cache npx di luar repo, karena jaringan npm diblokir sandbox. Tidak ada dependency atau file uji yang ditambahkan ke repo.

- **Alur peran** (1280px):
  - `/kasir` tanpa sesi → `/masuk?lanjut=/kasir`. Masuk Kasir → `/kasir`, menu "Kasir, Transaksi", chip "Ruang demo kasir · Berlaku sampai 12.54 WIB".
  - Refresh tetap masuk. Klik Transaksi → `aria-current` pindah dan fokus ke `main`; tombol Back kembali ke `/kasir`.
  - Kasir membuka `/dashboard` → halaman 403. **Ganti ke Pemilik** → 6 menu di ruang demo yang sama. **Ganti ke Kasir** saat di `/dashboard` → diarahkan ke `/kasir`.
  - `/tidak-ada` → 404 di dalam shell.
- **Keluar:** dialog terbuka, Escape menutupnya. Konfirmasi → `/masuk` dengan pesan "Kamu sudah keluar. Data ruang demo tadi sudah dihapus."; cookie browser tersisa 0.
- **Redirect aman:** `lanjut=https://contoh.invalid/x` → `/kasir`. Kasir dengan `lanjut=/laporan` → `/kasir`.
- **Penyimpanan:** `localStorage` dan `sessionStorage` kosong; `document.cookie` `""`. Cookie browser `seduh_session` `httpOnly=true sameSite=Strict path=/api`.
- **Error/retry** (360px):
  - `/api/session` diblokir → "Sesi belum bisa dimuat — Server belum bisa dihubungi…", lalu **Coba lagi** → `/masuk`.
  - Login 500 → notice dengan kode permintaan dan tombol peran aktif lagi; **Coba lagi** → `/kasir`.
  - Ganti peran saat offline → pesan di bawah topbar; **Coba lagi** berhasil dan pesan hilang.
- **Sesi kedaluwarsa** di SQLite lalu buka `/produk` → `/masuk?lanjut=/produk` dengan pesan "Sesi demo berakhir…". Masuk sebagai Pemilik → langsung ke `/produk`.
- **Responsif:** 360, 768, dan 1280px tanpa scroll horizontal di halaman masuk maupun shell (`scrollWidth − clientWidth = 0`).
  - 768px: sidebar ikon.
  - 360px: navigasi horizontal, tombol akun ikon saja dengan `aria-label`, dan dialog keluar muat di layar.
  - Item aktif (`/pengaturan`) berada di dalam area navigasi horizontal.
- **Keyboard:** Tab pertama di halaman masuk fokus ke pilihan Kasir dengan outline kuning `rgb(215,166,61)`, dan Enter langsung masuk. Tab pertama di shell memunculkan skip link (top 12px). Tab ke-4 berada di menu Transaksi dengan outline terlihat.
- **Console:** tidak ada `pageerror`. Satu-satunya log merah adalah respons jaringan 401 `GET /api/session` saat belum masuk, sesuai kontrak API.
- **Mode dev:** `npm run dev` (WEB_PORT 5175, PORT 3042, database sementara). `/dashboard` 200 lewat fallback SPA. Login lewat proxy Vite → 201 dengan cookie HttpOnly, dan `GET /api/session` lewat proxy mengembalikan sesi kasir.
- `npm run check` (lint, format, build) dan `git diff --check` lolos.

## Review dan verifikasi ulang

Review pada 15 Oktober 2026 melalui Chrome headless/Playwright, build produksi Express dan mode Vite. Semua proses memakai port acak, database sementara, dan konteks browser baru. Tidak menambah unit test atau dependency proyek.

- **Error logout tersembunyi:** sebelumnya pesan error berada di belakang dialog modal. Sekarang error dan kode permintaan ditampilkan di dalam dialog, dengan tombol "Coba keluar lagi". Batal/Escape menutup dialog saat tidak sibuk; retry dari notifikasi luar membuka konfirmasi kembali sebelum menghapus data. Escape tidak menutup dialog saat DELETE masih berjalan.
- **Respons API rusak:** respons sukses berupa HTML, JSON rusak, `null`, objek tanpa sesi, atau tanggal sesi invalid sekarang menghasilkan `INVALID_RESPONSE` dengan pesan yang ramah dan retry yang bekerja. Login gagal mengaktifkan kembali tombol peran. Field error non-string juga memakai pesan fallback agar UI tidak crash; 204 logout tetap diterima.
- **Judul tab:** setelah logout judul berubah menjadi "Masuk demo · Seduh POS", bukan judul halaman sebelumnya.
- **Navigasi selama ganti peran:** ketika owner menunggu respons ganti ke kasir lalu membuka Dashboard, hasil akhir sekarang diarahkan ke `/kasir`. Pemeriksaan memakai route terkini setelah respons tiba.
- **Regresi alur:** login kasir/pemilik, refresh sesi, menu per peran, 403/404, Back, fokus ke `main`, ganti peran pada workspace yang sama, dan redirect eksternal/peran terlarang lolos.
- **Cookie dan logout:** cookie HttpOnly/Strict dengan path `/api`, token tidak terlihat di `document.cookie`, localStorage/sessionStorage kosong; logout berhasil menghapus cookie dan workspace di SQLite.
- **API client asli melalui Vite:** POST produk oleh kasir mendapat 403 tanpa mengeluarkan sesi UI. Setelah sesi dicabut di SQLite, GET produk mendapat 401 dan listener global langsung mengarahkan UI ke halaman masuk dengan notice. Refresh sesi kedaluwarsa serta login ulang ke route tujuan juga lolos.
- **Responsif/keyboard:** 360, 768, dan 1280px tanpa overflow horizontal pada halaman masuk dan shell. Item menu aktif terlihat pada ponsel; fokus keyboard terlihat. Screenshot desktop dan dialog error 360px diperiksa secara visual.
- Tidak ada `pageerror` browser. `integrity_check`/`foreign_key_check` SQLite serta `npm run check` lolos, termasuk aturan maksimal 25 baris per fungsi.

- Listener 401 global sudah diuji dengan request produk melalui API client asli di Vite. Integrasi pada halaman fitur diperiksa lagi saat tiket halaman tersebut selesai.
- Firefox dan Safari belum diuji.
