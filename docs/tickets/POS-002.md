# POS-002 — Skema database, migrasi, dan seed

Status: Selesai
Prioritas: P0
Dependensi: POS-001

## Tujuan

Buat tabel demo_workspaces, sessions, products, transactions, transaction_items, settings, dan migration log.

## Kriteria penerimaan

- [x] Migrasi berurutan hanya diterapkan sekali dan berjalan dalam transaksi.
- [x] Semua data domain mempunyai workspace_id; indeks mendukung filter workspace/tanggal.
- [x] Harga/qty/stok memiliki batas dan constraint; total/disc dihitung sebagai integer rupiah.
- [x] Seed membuat menu Seduh dan contoh transaksi dengan tanggal relatif; seed tidak menggandakan data.
- [x] Identitas/item/harga/diskon disnapshot pada transaksi; idempotency_key unik per workspace.
- [x] Ada perintah migrate dan seed; data persisten setelah API restart.

## Verifikasi tanpa unit test

1. Jalankan migrasi dua kali dan pastikan hasil tetap sama.
2. Periksa constraint dengan SQLite; masukan tidak valid ditolak.
3. Restart API dan periksa data/seed masih tersedia.

## Bukti selesai

Verifikasi selesai pada 14 Oktober 2026 dengan Node 22.20.0 (SQLite 3.50.4), memakai `DATABASE_PATH` sementara sehingga `data/seduh.sqlite` pengembangan tidak tersentuh.

- `npm run db:migrate` dua kali: run pertama "Diterapkan: 001_initial_schema", run kedua "Skema sudah terbaru (versi 1)". Hash SHA-256 `sqlite_master` sama sebelum dan sesudah run kedua.
- Rollback: migrasi sementara `002` berisi CREATE TABLE lalu INSERT ke tabel yang tidak ada. Migrasi gagal dengan exit 1, tabel tidak tercipta, dan `schema_migrations` tetap hanya versi 1. File sementara dihapus.
- Checksum: checksum versi 1 diubah manual di database, lalu `db:migrate` berhenti dengan "Migrasi 001_initial_schema berubah setelah diterapkan."
- `npm run db:seed` dua kali: pertama "9 produk, 35 transaksi" (70 item), kedua "seed dilewati"; jumlah baris tidak bertambah.
- 21 masukan invalid ditolak SQLite: harga < 1.000, pecahan, dan teks; stok −1 dan 100.001; kategori asing; foto bukan preset; nama kosong; diskon 101%; nilai diskon/total/kembalian tidak cocok; uang kurang; QRIS dengan kembalian; tanggal bukan ISO; qty 0; line_total salah; idempotency_key dan nomor ganda dalam workspace; peran sesi asing; dan workspace yang tidak ada.
- Isolasi: workspace kedua di-seed (9 produk/35 transaksi). Item yang menunjuk produk workspace lain dan item yang dipindah workspace ditolak trigger. Menghapus workspace kedua menghapus seluruh datanya (0 sisa); workspace contoh tetap 35 transaksi.
- Snapshot: menghapus produk yang terjual 7 kali membuat `product_id` 7 item menjadi NULL, sedangkan nama dan harga snapshot tetap ada.
- `EXPLAIN QUERY PLAN` filter `workspace_id` + rentang `created_at` memakai `transactions_workspace_created_idx`. `PRAGMA integrity_check` ok dan `foreign_key_check` kosong.
- Tanggal relatif: `now` 08.00 WIB menghasilkan 30 transaksi (6 hari sebelumnya, belum ada hari ini). `now` 23.30 WIB menghasilkan 35 transaksi termasuk hari ini. `now` 00.05 WIB 2 Januari 2027 menghasilkan transaksi 27 Desember–1 Januari. Tidak ada transaksi di masa depan.
- Restart API (`PORT=3011`): start pertama pada database baru menjalankan migrasi dan health 200. Setelah `db:seed`, API dihentikan dan dijalankan lagi; migrasi 1, 9 produk, 35 transaksi, dan omzet Rp2.249.200 tetap sama. Seed ulang dilewati.
- `npm run check`: lint, format, dan build lolos. `git diff --check` lolos; `data/` tetap diabaikan Git.

## Review dan perbaikan

Review pada 14 Oktober 2026 menemukan dan memperbaiki:

- Produk bisa dipindah workspace dan meninggalkan referensi item struk lintas workspace. Migrasi baru `002_persistence_integrity.sql` menjadikan kepemilikan produk tetap; database yang sudah tercampur ditolak sebelum perubahan diterapkan.
- Nama log migrasi dapat diubah tanpa terdeteksi. Runner sekarang memeriksa nama, checksum, dan urutan log, termasuk pemeriksaan ulang di dalam transaksi.
- SQLite menerima timestamp jam 24 meskipun format aplikasi memakai jam 00–23. Migrasi 002 menormalisasi data lama dan menolak jam 24 pada INSERT/UPDATE selanjutnya.
- `busy_timeout` dipasang sebelum pengaturan WAL agar berlaku saat startup beberapa proses.

Verifikasi review memakai database sementara dan tidak membuat file unit test:

- Database baru menerapkan dua versi; pengulangan menerapkan nol migrasi. Upgrade database versi 1 mempertahankan 35 transaksi dan mengubah `2026-10-14T24:00:00.000Z` menjadi `2026-10-15T00:00:00.000Z`.
- Kegagalan pencatatan migrasi 002 mengembalikan seluruh skema dan log ke keadaan sebelum penerapan. Kepemilikan lama yang sudah tercampur juga membuat migrasi rollback.
- Seed dua workspace menghasilkan 70 transaksi; seed ulang tidak menambah data. Perpindahan workspace produk dan referensi item lintas workspace ditolak.
- Perubahan/hapus produk tidak merusak snapshot struk. Cascade workspace kedua tidak mengubah 35 transaksi workspace pertama.
- Jam 24 ditolak pada 11 kolom timestamp. Harga/stok/total/diskon/kembalian invalid juga ditolak; indeks tanggal, integrity check, dan foreign-key check lolos.
- Perubahan nama/checksum log dan versi log yang hilang ditolak. Empat proses migrasi bersamaan selesai dengan tepat dua catatan migrasi.
- Sampel waktu pagi, tengah malam, dan pergantian tahun tidak memiliki transaksi masa depan.
- Startup API otomatis menerapkan versi 2; seed CLI dua kali aman; restart API mempertahankan jumlah transaksi dan omzet. Healthcheck 200 sebelum dan setelah restart.
- `npm run check` dan `git diff --check` lolos. Batas fungsi 25 baris tetap berlaku. Database, env, dependency terpasang, dan build output diabaikan Git.
