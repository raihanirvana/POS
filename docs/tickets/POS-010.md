# POS-010 — Dashboard dan laporan penjualan

Status: Selesai
Prioritas: P1
Dependensi: POS-005, POS-006

## Tujuan

Agregasi server untuk dashboard, laporan periode, produk terlaris, dan CSV.

## Kriteria penerimaan

- [x] Endpoint /api/dashboard, /api/reports dan ekspor menghitung data workspace di server.
- [x] Tanggal hari ini dan batas periode inklusif memakai Asia/Jakarta.
- [x] Nilai pendapatan setelah diskon, rata-rata transaksi, unit terjual, stok menipis, dan grafik konsisten.
- [x] Laporan tidak mengklaim laba; rentang tanggal invalid ditolak.
- [x] CSV sesuai periode, aman dari formula injection, serta berbahasa Indonesia.

## Verifikasi tanpa unit test

1. Bandingkan transaksi contoh dengan total dashboard/laporan.
2. Coba batas tanggal, hasil kosong, rentang invalid, dan unduh CSV.

## Implementasi

**Server** (`routes/reports.js`, khusus pemilik):

- `services/report-service.js`:
  - Periode WIB inklusif dikonversi ke rentang UTC `[start, end)`.
  - Dashboard berisi hari ini, 7 hari, 4 favorit sepanjang waktu, stok ≤ 10, dan 5 transaksi terbaru.
  - Laporan berisi ringkasan, unit terjual, subtotal/diskon, tunai/QRIS, per hari (hari kosong = 0), dan 10 produk terlaris.
- `repositories/report-repository.js`:
  - Agregasi SQL berparameter yang selalu memakai `workspace_id` dan indeks `(workspace_id, created_at)`. Hari WIB dihitung dengan `date(created_at, '+7 hours')`.
  - Produk terlaris dikelompokkan per `product_id`, atau per nama snapshot bila menu dihapus. Nama mengikuti waktu penjualan terakhir (`ROW_NUMBER()` berdasarkan `created_at DESC, id DESC`); setiap kelompok memiliki `id` stabil, termasuk ketika nama menu sama.
- `services/report-export-service.js` + `lib/csv.js`: CSV dengan header Indonesia, BOM, dan CRLF. Semua sel dikutip, dan sel berawalan `= + - @ \t \r` diberi `'`.
- `validation/report-validation.js`: `from`/`to` wajib dan berupa tanggal kalender nyata (`isDateKey` di `validation/common.js`), `from ≤ to`, maksimal 366 hari.

**Client:**

- `/dashboard`: 4 tile hari ini, grafik penjualan 7 hari, favorit pelanggan, 5 transaksi terbaru (Lihat struk memakai dialog POS-009), dan catatan stok menipis dengan tautan ke Produk.
- `/laporan`:
  - Filter periode di satu baris atas: dua tanggal WIB dan preset Hari ini / 7 / 30 hari. Validasi klien sama dengan server, dan isian invalid tidak mengganti periode yang tampil.
  - Isi: 4 tile, kalimat "Subtotal − diskon = pendapatan … **bukan laba**", tunai/QRIS, grafik per hari (≤ 31 hari, hari tertinggi disorot) atau tabel (> 31 hari), dan 10 produk terlaris.
  - **Ekspor CSV** mengunduh file dari server untuk periode yang tampil (`apiDownload`, dengan error JSON dan 401 tetap ditangani).
- **Grafik** (`components/charts/`), mengikuti skill dataviz:
  - Satu seri kolom tanpa legenda. Batang ≤ 24px dengan ujung atas membulat 4px, jarak 2px, dan gridline hairline solid; label sumbu ringkas ("Rp 250 rb").
  - Hanya kolom yang disorot (hari ini atau hari tertinggi) yang diberi label nilai.
  - Tiap kolom bisa difokus keyboard dengan `aria-label` lengkap. Tooltip CSS muncul saat hover/fokus pada seluruh slot, dan ditempatkan di dalam area grafik; fokus keyboard didahulukan agar tidak ada dua tooltip bersamaan.
  - Tampilan tabel tersedia lewat "Lihat data sebagai tabel".
  - Warna: hijau daun `#285a46` untuk sorotan dan `#6b9a82` untuk hari lain. Validator palet menunjukkan kontras keduanya ≥ 3:1 terhadap putih dan ΔE 21,9 antar keduanya. Hijau muda prototype `#9dbfab` (1,95:1) diganti.
- **Bersama:** `useRemoteData` (abort, data lama tetap tampil) dan `RemoteContent` (memuat, error, coba lagi, redup saat refresh) dipakai Dashboard dan Laporan.

  - Pelanggan `=HYPERLINK("…")`, `+SUM(1,1)`, `-2+3`, dan `@cmd` menjadi `'=HYPERLINK(""…"")`, `'+SUM(1,1)`, `'-2+3`, `'@cmd`. `Nadia, "Kopi" Lover` dikutip dengan benar.

## Review dan perbaikan — 15 Oktober 2026

- Ekspor sebelumnya memakai periode yang baru diminta saat data periode lama masih terlihat. Sekarang tombol dan retry ekspor hanya aktif setelah respons valid untuk periode pilihan selesai dimuat. Pesan unduhan menyebut periode file.
- `9999-12-31` sebelumnya membuat pengisian hari berulang tanpa akhir. Batas UTC dihitung dari waktu akhir ditambah satu hari dan iterasi berhenti pada tanggal akhir. Tahun `0000` dibatasi ke timestamp minimum yang bisa tersimpan. Waktu CSV memakai empat digit tahun, termasuk `0000`.
- Respons laporan/dashboard divalidasi sebelum ditampilkan: tanggal kalender nyata, periode sesuai request, urutan/jumlah hari, rata-rata, total harian/metode, hitungan transaksi, preset foto, dan identitas produk. Respons invalid menampilkan error dan Coba lagi. CSV dengan MIME/metadata invalid atau body kosong ditolak.
- Agregasi dashboard/laporan berjalan dalam transaksi baca SQLite supaya seluruh query memakai snapshot yang sama saat proses API lain melakukan checkout. Transaksi tulis tetap `BEGIN IMMEDIATE`.
- Produk terlaris memakai waktu transaksi terakhir, dengan id item sebagai pemutus seri. Menu bernama sama mempunyai key terpisah. Tabel transaksi dashboard memakai aturan pembungkusan pelanggan yang sama dengan riwayat.
- Tooltip periode 30 hari sebelumnya keluar dari layar di dekat ujung grafik. Tooltip sekarang dibatasi area grafik; hover tidak memunculkan tooltip kedua saat kolom mendapat fokus keyboard.

Verifikasi tambahan memakai build produksi, database/port sementara, SQL dan Chrome melalui Playwright, tanpa unit test atau dependency baru:

- Dua proses API: 150 checkout bersamaan dengan 150 pembacaan laporan; semua jumlah harian/metode cocok dengan ringkasan.
- Ringkasan pendapatan, jumlah, rata-rata, subtotal, diskon, unit, dan stok menipis cocok dengan SQL. Tanpa sesi 401; kasir dengan `X-Role: owner` tetap 403 pada ketiga endpoint. Query workspace asing tidak memindahkan ruang data.
- Penjualan nyata di timestamp UTC tahun 0000 dan 9999 masuk hari WIB yang benar; penjualan pada 00.00 WIB hari berikutnya dikecualikan. CSV mempertahankan tanggal empat digit. Rentang invalid/ganda mendapat 400.
- Fixture checkout pada 23:59:59.999 dan 00:00 WIB masuk tanggal berbeda. Jumlah baris dan penjumlahan total CSV cocok dengan laporan; BOM, CRLF, kutip/koma, dan awalan formula diperiksa.
- Dua menu bernama sama tampil terpisah; transaksi lama yang dimasukkan setelah transaksi baru tetap memilih nama snapshot menurut waktu penjualan.
- Ekspor nonaktif saat ganti periode tertunda atau gagal, lalu aktif setelah Coba lagi berhasil. Delapan respons laporan yang rusak dan tiga respons CSV invalid menampilkan error tanpa halaman blank.
- Unduhan Chrome mempunyai nama sesuai periode yang terlihat. Cookie yang dicabut saat ekspor mengembalikan pengguna ke halaman masuk.
- Nama pelanggan 60 karakter tidak membuat tabel dashboard melebar pada 360, 768, dan 1280px. Laporan juga tidak melebar; seluruh 30 tooltip diuji dengan keyboard pada 360px dan hanya satu tooltip terlihat.
- Periode 30 hari tampil sebagai grafik; periode lebih panjang sebagai tabel. Rentang terbalik menonaktifkan ekspor.
- Regresi POS-005, POS-006, POS-008, dan POS-009 dijalankan ulang. Integritas SQLite dan foreign key lolos; tidak ada `pageerror` atau error API tak terduga.

Batas tahap ini:

- Laporan menghitung pendapatan, bukan laba; biaya bahan dan operasional tidak dicatat.
- Favorit dashboard memakai data sepanjang waktu, sedangkan produk terlaris laporan memakai periode.
- Produk yang diganti nama dihitung sebagai satu produk (per `product_id`) dengan nama snapshot terbaru. Menu yang sudah dihapus dikelompokkan per nama snapshot.
- Dashboard tidak memuat ulang otomatis; angka diperbarui saat halaman dibuka lagi. CSV membaca data saat ekspor, sehingga penjualan baru dari tab lain dapat mengubah jumlah dibanding laporan yang sebelumnya dimuat.
- Tidak ada mode gelap, karena seluruh aplikasi memakai tema terang DESIGN.md.
- CSV diuji di file dan header; pembukaan di Excel/Google Sheets tidak diuji langsung.
- Firefox dan Safari belum diuji.
